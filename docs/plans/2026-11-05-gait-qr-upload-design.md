# 步态视频扫码上传与解码兼容设计

## 目标

治疗师在电脑端生成左右侧二维码，手机扫码后选择原始视频，电脑自动接收对应视频。传输过程不经过聊天软件压缩，手机和电脑分别计算 SHA-256，确认文件一致。浏览器不能原生解码时，在本地完成常见编码的软件转换，再继续逐帧识别。

## 数据流

1. 电脑为指定侧创建一次性上传会话，显示包含随机会话标识和密钥的二维码。
2. 手机打开上传页，从相册或文件管理器选择视频，计算 SHA-256 并上传到 Supabase 私有桶。
3. 手机完成上传后，服务端会话记录文件大小、类型、校验值和对象路径。
4. 电脑轮询会话，下载原始文件并重新计算 SHA-256。校验不一致时拒绝导入。
5. 电脑确认接收后删除云端对象并关闭会话。过期会话由清理函数关闭，存储对象按对象路径和有效期清理。
6. 视频优先走浏览器原生解码。出现 `0×0` 时，动态加载软件解码组件，在浏览器本地转换为 H.264/MP4 后重试。

## 安全与隐私

- 存储桶保持私有，不创建公开链接。
- 会话密钥使用加密随机数，上传、下载、完成和删除操作都校验会话及有效期。
- 数据库和存储策略只开放所需操作，不开放对象列表。
- 云端只临时保存视频，电脑接收后立即删除；页面不记录患者身份信息到上传会话。
- Supabase 配置和密钥继续使用现有匿名公开配置，私有数据由随机会话密钥保护，不引入服务端密钥。

## 错误处理

- 二维码过期、已使用或密钥不匹配时，手机端显示明确原因，电脑端可重新生成。
- 上传中断时保留重试入口，不把部分文件标记为就绪。
- 校验失败时拒绝导入并删除异常文件。
- 原生解码失败时显示软件转换进度；软件转换失败时保留原文件和人工重传入口。
- Supabase 未配置或迁移未执行时，保留现有电脑文件上传方式并显示配置提示。

## 验证

- 单元测试覆盖会话状态、二维码地址、文件校验、过期和错误路径。
- 使用同一段 HEVC 文件验证手机上传页到电脑端的完整流程及 SHA-256 一致性。
- 在 Edge 验证原生 `0×0` 后软件转换并识别，在 Chrome 验证原生快速路径。
- 回归双视频、人工时相、代表帧截图、报告、刷新恢复、构建和现有全部测试。
