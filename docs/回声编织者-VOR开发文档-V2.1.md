## 2. 全局核心设计原则

**（1）医学硬性原则（不可违背）**

- **训练靶点**：前庭眼动反射（VOR）中的固视维持与抑制功能。
- **核心动作**：玩家头部做规定轴、规定幅度、规定频率的往复运动；双眼始终注视**视网膜上固定的核心光球**（固定屏幕模态 = 屏幕上的不动点，头显模态 = 世界空间不动点，见 2(3)），不允许主动扫视或追踪边缘目标。
- **头部活动范围**：水平（Yaw）±20°，垂直（Pitch）±15°。超出范围时显示视觉警告，但**不断开连接**，自动柔性地将输入限制在边界。
- **频率范围**：0.3 Hz ~ 1.2 Hz，禁止超出。
- **训练节奏**：所有训练以"20 秒训练块 + 10 秒休息块"为最小单元（见 3.7），任何章节不得要求连续训练超过 20 秒。
- **单次训练时长**：每章节有效训练 3~6 分钟（不含休息），不超过 8 分钟；**单日有效训练总量 ≤ 20 分钟**（儿童默认值，治疗师可调，见 3.4.5）。
- **禁止诱发光敏性癫痫**：全屏及边缘高对比度闪烁频率必须避开 3~30 Hz；所有闪烁使用渐变或低于 3 Hz 的变化。
- **禁止强制头部快速运动**：所有训练频率渐变引入，不允许瞬间跳变。
- **症状闭环**：每次训练前后做症状 VAS 评分，加重超限即停止（见 3.4.4）。

**（2）核心交互原则**

- **唯一输入**：头部姿态（Yaw/Pitch，来自 DeviceOrientation / WebSerial / WebBluetooth IMU，见 3.2）与眼动追踪（可选，WebXR）或头部微小颤动间接判定。
- **唯一目标**：核心光球——在视网膜上保持固定（实现方式按显示模态，见 2(3)）。
- **唯一成功条件**：在规定的头动模式下，持续保持注视偏差 < 2.5°（有眼动时），且头部角加速度平滑（低于动态阈值，见 3.3.1）。
- **惩罚机制**：视觉/听觉警告，不影响训练继续，不扣分到负值。

**（3）核心光球锚定与显示模态（关键，V2.1 二次修正）**

V2.0 规定"光球必须锚定世界空间、相机随头 1:1 旋转、禁止屏幕锚定"。**经生物力学推算，该规定只对头显成立**；在固定屏幕上它是错的，V2.1 更正为按显示模态分流：

- **模态 A · 固定屏幕（默认，覆盖绝大多数用户）**：桌面显示器，或支架固定的手机/平板。
  - 光球**锚定在屏幕中心**（屏幕层 3D 叠加渲染，不随头动偏移）。这在物理上就是"世界固定"：用户转头 20°，眼球必须反向转 20° 才能持续盯住屏幕上那个不动的物理点——这正是标准 VOR ×1 训练，与真实墙面靶标等效。
  - **反例（V2.0 方案在固定屏幕上的错误）**：相机随头 1:1 旋转时，光球在屏幕上反向偏移一个头转角；用户头已转向 20°，视线需再偏 20° 去追屏幕上的光球 → 总眼/头比 ≈ 2:1，构成 VOR ×2 的错误刺激，且超出多数患者舒适眼位。
  - 世界层（背景、道具、干扰物）按头动**反向平移**（头向右 → 世界内容向左），提供与头动一致的光流线索；映射增益沿用现有 2D VOR 模式调参（±20° → ±0.32 屏宽，`docs/vor-mode.md`），可调。
- **模态 B · 头显（WebXR，可选，二期）**：
  - 相机随头 1:1 旋转，光球**锚定在世界空间** (0,0,4.5)，屏幕投影随头动自然偏移，由 VOR 反向眼动保持视网膜中央——这是 V2.0 原始设计，在头显下正确。
  - 可见性规格见 3.1.3。
- **模态切换**：`window.__vorDisplayMode = 'fixed' | 'hmd'`，默认 `'fixed'`；进入 WebXR 会话自动切 `'hmd'`。训练参数（轴/幅度/频率/判定）两种模态完全一致，仅渲染映射不同。
- 光球视觉上可带轻微呼吸光晕和粒子拖尾增强注视吸引力，但**不得**随玩家头部移动（模态 A 钉屏幕中心；模态 B 钉世界坐标）。
- **可见性保证**：模态 A 光球钉屏幕中心，天然全程可见；模态 B 在 yaw±20° / pitch±15° 极限头位下光球必须仍在视野内，相机规格见 3.1.3。

**（4）视觉与心理原则**

- 游戏将训练包装成"施法仪式"：核心光球是"灵魂之种"，头部运动是"注入灵魂"的摆动。
- 章节制解锁，每章通关解锁新世界/新形态，利用蔡格尼克效应。
- 成功抑制扫视冲动时给予更强正反馈（蓝光+空灵竖琴音），强化抑制行为。

## 3. 全局系统架构

### 3.1 技术栈与平台适配

#### 3.1.1 平台决策

- **运行形态**：Web 页面（`vor.html`），与本仓库其他模块一致，GitHub Pages 静态部署，无需安装。
- **渲染**：three.js（复用仓库 `assets/vendor/` 已有的 three 构建与 GLTFLoader；`src/game-3d/` 已验证的模块化组织方式：`main.js` 入口 + 单职责模块）。
- **模型**：glTF/GLB（仓库 `models/` 已有 GLB 资产管线与 `optimize-models.sh` 优化脚本，沿用）。
- **后端**：Supabase（复用现有项目 `bydijxssezoetquounqo.supabase.co` 与 `assets/cognitive/reports/qnr-supabase.js` 客户端模式），详见第 5 章。
- **目标设备**：桌面 Chrome/Edge（WebSerial 可用）、Android 手机+平板（DeviceOrientation + WebBluetooth）、iOS 13+（DeviceOrientation，需 `requestPermission`，`input.js` 已处理）。

#### 3.1.3 显示模态与相机规格（V2.1 重写，硬性）

**模态 A · 固定屏幕（默认）**：

- 光球固定渲染于屏幕中心（独立 3D 叠加场景，固定 NDC (0,0)），物理直径按观看距离换算：`d = 2 × D × tan(1.9°)`（D=60cm 时 ≈ 4.0cm，视角 ≈ 3.8°，与 0.3m@4.5m 等效）；D 为设置项（40~100cm，默认 60），校准时引导用户按提示就座（3.2.4）。
- 世界层反向平移增益默认 ±0.32 屏宽 / ±20°（沿用现有 2D VOR 调参）；背景资源必须覆盖最大平移后的视口（四周预留 ≥ 35% 屏宽的出血），不得露出边缘接缝。
- 最小视口 1024×640；手机必须横屏 + 支架固定（3.2.4）。
- 相机 FOV 在模态 A 不参与训练刺激（仅决定场景透视），取 vFOV 50° 即可。

**模态 B · 头显（WebXR，二期）**：

- 相机随头部 1:1 旋转，光球锚定世界空间，极限头位下屏幕偏移角等于头部转角。为保证光球全程可见：
- **垂直 FOV ≥ 50°**（默认 50°）：半视角 25°，pitch 极限 15° 后仍余 10° 边距，大于光球视角半径（0.3m @ 4.5m ≈ 3.8° 直径，半径 1.9°）。
- **水平 FOV ≥ 56°**（16:9 下 vFOV 50° 对应 hFOV ≈ 75°，满足；4:3 下 hFOV ≈ 64°，满足）。

#### 3.1.4 渲染分层约定（沿用现有 VOR 模式教训，按模态分列）

参照 `docs/vor-mode.md` 的三层渲染语义：

| 层 | 内容 | 模态 A（固定屏幕） | 模态 B（头显） |
|---|---|---|---|
| 远景层 | 天空盒、远景剪影 | 反向平移（可用弱增益；无特征远景可不动，避免边缘接缝） | 不随头动（无限远，无视差） |
| 世界层 | 场景道具、干扰物 | 反向平移（±0.32 屏宽 / ±20°） | 世界空间，相机随头转动自然偏移 |
| 屏幕层 | **核心光球** | **钉屏幕中心**（独立叠加场景） | —（光球在世界层） |
| 屏幕层 | HUD（角度条、平滑度仪表、蓄力条、节拍点） | 钉屏幕，半透明 | 钉屏幕，半透明 |

注意（两种模态的共同根基，E2E 必须覆盖，见 6.4）：光球在**视网膜上必须固定**——模态 A 靠屏幕锚定实现，模态 B 靠世界锚定 + VOR 实现；HUD 永远钉屏幕层，不得挂进世界空间。模态 A 下若误把光球放进世界层（会随反向平移跑掉），或模态 B 下误把光球放进屏幕层（VOR 刺激消失），都是破坏训练意义的硬错误。

### 3.2 输入系统

#### 3.2.1 头部姿态输入（必须）

数据来源按优先级（自动探测，可手动覆盖）：

1. **WebSerial IMU**（桌面，九轴模块串口直连，采样率最稳，≥100Hz）；
2. **WebBluetooth BLE IMU**（桌面/安卓，≥60Hz）；
3. **DeviceOrientation**（手机/平板内置 IMU，复用 `src/game-3d/input.js` 的探测与 iOS 权限处理；`alpha/beta/gamma` → yaw/pitch/roll，采样率约 60Hz）；
4. **模拟注入**（开发与 E2E）：`window.updateFromGyroscope({yaw, pitch, roll, t})`，与现有 2D VOR 模式同一注入通道；无硬件时也可用键盘脚本生成正弦波形（`window.__vorSimulate({axis, amp, freq})`）。**键盘/模拟仅用于开发与 E2E，正式患者会话禁用。**

统一规格：

- **数据格式**：内部统一 `{ yaw, pitch, roll, t }`（度 + 秒，`performance.now()` 时基）；外部设备 JSON 或二进制帧在适配层转换。
- **采样率** ≥ 60 Hz；低于 30 Hz 判定设备不合格并提示。
- **滤波**：互补滤波或一阶低通 + 零漂补偿；消除高频抖动但不引入 >50ms 延迟。
- **信号链（V2.1 补充，硬性）**：原始角度先重采样到 100Hz 均匀网格（线性插值），在网格上差分得 ω；ω 经一阶低通（截止 8Hz——训练信号最高 1.2Hz，裕度充足）后差分得 α。**单帧 dt > 50ms 不得跨帧差分**（该帧 ω/α 作废），防止切后台/卡顿后的 dt 尖刺被误判为头部毛刺。
- **输入源标记**：每条会话记录 `input_source`（serial / ble / deviceorientation / sim / keyboard）；键盘与模拟输入产生的会话一律标记 `"clinical": false`，不计入疗效统计。
- **零点标定**：每次训练开始前，要求玩家头部中立位静置 2 秒，计算零漂并补偿（复用 `input.js` 的 `_gyroBase` 归零模式）。
- **角度限制**：Yaw 截断在 [-20°, +20°]，Pitch 截断在 [-15°, +15°]；超出部分截断并触发边缘红色警告；原始（未截断）值仍记录。
- **映射**：Yaw → 模态 A 世界层反向平移 / 模态 B 相机 Y 轴旋转；Pitch 同理；Roll 忽略（仅用于异常姿态检测，见 6.1）。
- **丢帧与时间戳对齐**：所有样本以到达时刻 `performance.now()` 打戳；采样间隔 >100ms 记为 gap，gap 期间判定系统暂停（不计错误），>2s 按设备断连处理（见 6.1）。

#### 3.2.2 眼动追踪输入（可选，但强烈推荐）

- **数据来源**：WebXR 兼容头显的 eye tracking（如支持 `XRView.eye` 的设备），或桌面 Tobii 等外置眼动仪的 WebSocket 桥。
- **不支持的来源**：普通 webcam 眼动估计（精度约 2~4°）达不到 2.5° 阈值要求，**不得**作为固视判定输入；可选作"是否注视屏幕"的粗粒度出席检测，不参与判定。
- **采样率** ≥ 60 Hz，精度 ≤ 1°。
- **注视点投射**：将注视方向投射到世界空间，计算与核心光球中心的角度偏差。
- **偏差阈值**：成功固视要求偏差 < 2.5°。参考尺寸：光球 0.3m @ 4.5m，视角直径约 3.8°，即允许视线略偏出光球边缘但不得远离。
- **无眼动追踪时降级方案**：使用头部微小颤动（角加速度 RMS）和头部朝向边缘干扰物的补偿性急动作为间接指标，判定固视质量。**诚实条款见 3.2.3。**

#### 3.2.3 无眼动追踪的诚实条款（新增，不可删）

- 头不动 ≠ 眼在看。无眼动仪时，系统**无法验证**患者是否真在固视，"固视合格"仅是基于头部平滑度的**近似判定**，数据中必须标注 `"fixation_mode": "inferred"`。
- 因此：第四章（抑制反射）与第七章（长时程固视）这两章的核心卖点依赖扫视检测，**无眼动仪时医学有效性无法保证**，界面必须向治疗师明示"该章结果为近似判定"。
- 疗效声明收敛：对治疗师与家长的文案统一为"头部运动质量指标"，不得声称"VOR 增益改善"——VOR 增益本身需要眼动数据才能计算。
- 最低硬件推荐：DeviceOrientation 手机可完成全部头部运动训练；眼动仪为第四章/第七章的强烈推荐项。

#### 3.2.4 会话运行环境与设备摆放（V2.1 新增，硬性）

- **典型部署（主场景）**：电脑显示器（Chrome/Edge）+ 头戴 BLE IMU；手机/平板仅作备用显示设备（支架固定横屏），DeviceOrientation 仅作备用传感器。
- **坐姿与固定**：全程坐姿，椅子无滑轮、有靠背；显示设备必须固定（显示器/支架），**禁止手持**（手持时设备跟头一起动，头动信号全毁）。入门流程用图示引导佩戴与摆放。
- **屏幕常亮**：会话期间申请 Screen Wake Lock；`visibilitychange` 回到可见时重新申请。不支持时提示用户手动关闭自动锁屏。
- **切后台/锁屏**：`visibilitychange → hidden` 立即暂停会话（冻结块计时、静音、判定挂起），回前台显示恢复确认后再继续；`pagehide` 保存进度（6.2）。
- **屏幕方向**：尽量锁定横屏（`screen.orientation.lock('landscape')`，不支持则引导手动）；方向变化立即暂停并重新标定。DeviceOrientation 的 yaw/pitch 提取必须按 `screen.orientation.angle` 补偿，且使用**相对校准零点的角度**，不用绝对罗盘方位（磁干扰与漂移）。
- **音频解锁**：`AudioContext` 在用户首次点击"开始训练"手势中创建/resume；节拍器用音频时钟调度，HUD 节拍点用 `performance.now()` 对齐。
- **观看距离**：校准流程第 0 步引导用户按 D（默认 60cm）就座，光球物理尺寸按 3.1.3 换算。
- **首次引导顺序**：筛查问卷（3.4.1）→ 设备摆放教学（本节图示）→ 观看距离确认 → 校准（3.4.2）。

### 3.3 核心判定系统

#### 3.3.1 摆动平滑度判定（V2.1 修复：动态阈值）

**V2.0 的固定阈值 150 °/s³ 在数学上不成立，本节重新定义。**

术语统一（全文一致）：

- `ω(t)`：头部角速度（°/s），由 yaw/pitch 差分得到；
- `α(t) = dω/dt`：头部**角加速度**（°/s²），作为平滑度指标；
- 物理 jerk（d²θ/dt³，°/s³）不使用——V2.0 混用了该术语与单位，特此更正。

**为什么固定阈值不成立**：正弦摆动 θ = A·sin(2πf·t) 的角加速度峰值为 `A·(2πf)²`，它随频率平方增长：

| 章节参数 | α 峰值（理想正弦） | α RMS（峰值/√2） | V2.0 阈值 150 判定 |
|---|---|---|---|
| 0.5Hz / ±15°（第一章） | ≈148 °/s² | ≈105 | 勉强擦线 |
| 1.0Hz / ±10°（第三章起步） | ≈395 | ≈279 | **永远超标** |
| 1.2Hz / ±10°（第三章目标） | ≈568 | ≈402 | **永远超标** |
| 0.3Hz / ±5°（第七章） | ≈17.8 | ≈12.6 | 过松，失去意义 |

即 V2.0 下第三章的"完美周期"不可能达成。**V2.1 改为按章节参数动态计算**：

```
alpha_threshold(A, f) = k × A × (2πf)² / √2        // 与 RMS 比较
                      （k = 1.3，余量系数，附录 A 可配置）
```

| 章节参数 | alpha_threshold（k=1.3） | 理想正弦 RMS | 判定 |
|---|---|---|---|
| 0.5Hz / ±15° | ≈136 °/s² | ≈105 | ✓ 有 30% 余量 |
| 1.0Hz / ±10° | ≈363 | ≈279 | ✓ |
| 1.2Hz / ±10° | ≈523 | ≈402 | ✓ |
| 0.3Hz / ±5° | ≈16.3 | ≈12.6 | ✓ |

- **窗口**：滑动窗口 0.5 秒，计算窗口内 α 的 RMS。
- **输出**：每个时间点输出布尔值 `isSmooth = (alpha_RMS < alpha_threshold(A当前, f当前))`，其中 A/f 取当前章节当前档位（自适应难度会调整，见 3.8）。
- **备选方案**（记录备查，不实现）：实测 ω 曲线与理想正弦的归一化残差。理论更优雅，但需要相位锁定，实现复杂；动态阈值方案简单且足够，K3 生成代码时优先使用动态阈值。

#### 3.3.2 摆动周期识别（V2.1 修复：比例死区）

- **轴识别**：根据角速度幅值判断主导轴（水平或垂直）。
- **死区（V2.1 修复）**：`deadzone = min(5 °/s, 0.3 × A × 2πf)`。
  - 原因：第七章 0.3Hz / ±5° 的峰值角速度仅 ≈9.4°/s，固定 5°/s 死区会让一个周期的大部分时间处于死区内，周期识别被切碎。
  - 示例：第一章 0.5Hz/±15° → min(5, 14.1) = 5°/s；第七章 → min(5, 2.8) = 2.8°/s。
- **零交叉检测**：主导轴角速度符号变化且越过死区，记录中位点。
- **幅度校验**：一次完整周期（中→左→中→右→中）的峰值角度落在 `A ± 2°`。
- **频率校验**：周期时长在 `1/f ± 10%`。

#### 3.3.3 完美周期判定（统一判据）

一个完整周期判为"完美"当且仅当：

1. 峰值幅度 ∈ `A ± 2°`；
2. 周期时长 ∈ `1/f ± 10%`；
3. 整个周期内 `isSmooth` 恒为真（动态阈值）；
4. 注视偏差 < 2.5°（有眼动时）；无眼动时以"未出现朝向干扰物的头部急动"替代，并标注近似判定。

#### 3.3.4 固视判定

- **有眼动追踪**：注视偏差 < 2.5° 持续一定时长；扫视事件 = 眼动速度 > 30°/s。
- **无眼动追踪**（近似判定）：
  - 头部在摆动过程中未出现朝向边缘干扰物的急动（角速度突变 > 50°/s 且方向指向干扰物）；
  - 头部摆动平滑度达标；
  - 视为"固视合格"，数据标注 `"fixation_mode": "inferred"`。

### 3.4 安全与校准系统

#### 3.4.1 训练前筛查问卷（强制，含排除标准）

首次使用前强制填写（复用仓库问卷模块的页面模式），任一排除项命中则**禁止进入训练**并提示就医咨询：

- 眩晕病史：近 3 个月有未确诊的急性眩晕发作 → 排除，建议先就医；
- 光敏性癫痫史（本人或一级亲属） → 排除；
- 颈椎急性损伤/不稳、近期颈部手术 → 排除；
- 严重心血管疾病、未控制的高血压 → 排除；
- 年龄 < 6 岁 → 排除（无法可靠配合指令）；6~12 岁需家长陪同确认；
- 当前正在服用前庭抑制药物 → 警告并提示咨询医生（不强制排除）。

问卷结果与每次会话记录关联存储；每 30 天重新确认一次。

#### 3.4.2 校准流程

1. 头部中立位静置 2 秒（零漂补偿）；
2. 眼动校准（若使用眼动仪）：依次注视屏幕上 5 个点；
3. 测试摆动（低幅度 10°、0.5Hz 水平摆动 10 秒），实时显示平滑度反馈，确保设备正常；校准漂移过大（零点偏移 > 3°）或采样率不足时给出明确错误提示并允许重试，连续 3 次失败则中止并提示检查设备。

#### 3.4.3 实时监控

- 若连续 3 秒 α RMS 严重超标（> 2 × 动态阈值），自动降低目标频率 0.1 Hz（走 3.8 的降级链）；
- 若头部超出限制角度超过 1 秒，显示警告并自动暂停当前训练块（不计错误）；
- Roll 持续 > 10° 超过 2 秒：提示"请保持头部正直，不要歪头"。

#### 3.4.4 症状闭环（V2.1 新增，硬性）

前庭康复的标准做法：每次训练监测症状变化，用症状驱动停止与降级。

- **每次会话开始前**：头晕 + 恶心 VAS 评分（0–10 各一项，大号按钮，儿童可用表情量表）。
- **每次会话结束后**：再次评分。
- **判定规则**：
  - 任一项加重 **> 2 分** → 当日训练立即终止，显示休息建议与"若持续不适请就医"提示，并记录事件上报治疗师；
  - 任一项加重 **1~2 分** → 本次会话可结束，但下次会话自适应难度整体降一档（3.8）；
  - 训练中玩家主动点"我不舒服"按钮（全程可见）→ 等同 >2 分处理。
- **训练中实时问询**：每章结束后（非训练中）显示一次 5 秒快速确认"感觉如何？很好/还行/难受"，"难受"触发提前结束流程。

#### 3.4.5 剂量上限（V2.1 新增，硬性）

- **单日有效训练总量 ≤ 20 分钟**（儿童默认，治疗师可在处方中调整为 10/15/20/30 分钟）；达到上限后当日只能进入第八章沙盒的"回顾模式"（不产生新训练数据）。
- **单次会话总长 ≤ 30 分钟**（含休息与过渡），到点强制收尾。
- **两章之间**：强制 ≥ 60 秒过场/休息，不得连续无缝刷章。

#### 3.4.6 紧急退出

玩家可通过点击屏幕右上角常驻按钮、键盘 Esc、或语音命令"停止"（Web Speech API，可选开启）立即停止训练，场景切换到安全休息画面（静态、低亮度、无运动元素）。

### 3.5 UI/HUD系统

- **核心光球**：位于世界空间（见 2.3），屏幕投影因头动而自然变化。光球本身带有呼吸光晕，中心有高亮小点。
- **HUD 元素**（全部 DOM/Canvas2D 屏幕层，半透明，不遮挡核心光球）：
  - **角度指示条**：屏幕顶部弧形条，显示当前 Yaw/Pitch 角度，超限部分变红（沿用现有 VOR 模式顶部角度条样式：青=未到位、绿=到位、琥珀=超范围）；
  - **平滑度仪表**：左下角小型波形图或颜色指示器（绿=平滑，黄=轻微毛刺，红=毛刺）；
  - **章节进度**：右上角图标+填充度；
  - **节拍器提示**：屏幕中下方视觉节拍点，与听觉节拍同步，**不得遮挡核心光球**；
  - **训练块倒计时**：环形条显示当前 Active 块剩余 20 秒（3.7）；Rest 块切换为呼吸光圈；
  - **症状按钮**：右上角常驻"我不舒服"（3.4.4）。
- **警告提示**：超出角度时屏幕边缘半透明红色渐变；检测到扫视时核心光球周围一次短暂红色波纹。
- **无障碍双编码**：所有用颜色传达的状态必须同时有形状/文字编码（如平滑度用 ●▲■ 三形 + 颜色），红/蓝光条附加形状差异（第二章），色盲模式下可切换为高对比配色。
- **所有 HUD 元素必须半透明且不影响核心光球注视。**

### 3.7 训练节奏控制器（TrainingPaceController）

> 本节合并 V2.0 文末补丁，为全局强制机制。医学依据：间歇式训练避免前庭神经元疲劳，维持 VOR 增益；休息期间前庭系统恢复，眼动反射保持敏锐。默认 20 秒训练 / 10 秒休息；患者不适时治疗师可调整为 15 秒 / 15 秒。

#### 3.7.1 状态机

```
状态: Active
  持续 active_block_sec（默认 20 秒）
  要求玩家按章节指定轴/幅度/频率摆动
  核心光球高亮（100% 章节主色），节拍器激活，判定系统运行
  HUD 显示 20 秒倒计时环形条

状态: Rest
  持续 rest_block_sec（默认 10 秒；垂直训练章节 15 秒）
  要求玩家头部回中，保持静止（不强制判定，仅温和"归中"引导环提示）
  核心光球降至 30% 亮度、柔和白/淡绿色，节拍器停止，所有任务目标与干扰源暂停
  HUD 显示"放松，目视前方，深呼吸"+ 缓慢扩散的呼吸光圈
  判定系统暂停，不记录错误

状态转换:
  Active -> Rest: 计时器到点
  Rest -> Active: 计时器到点，播放轻柔提示音，光球渐亮，节拍器重启
```

> **块边界归属**：摆动周期按"周期完成时刻"计入所在块；Rest 期间判定暂停，跨块边界的半个周期不计入任何块，亦不记错误。

#### 3.7.2 章节适配

| 章节 | Active 块内容 | Rest 块 | 有效训练目标 |
|---|---|---|---|
| 一 机械鸟 | 连续水平摆动（0.5Hz，理论 10 周期） | 回中静止 | 4 分钟（12 块） |
| 二 钟楼 | 1~2 个悬停序列 | 回中静止 | 4 分钟 |
| 三 游乐园 | 高频水平摆动，木马减速 | 回中静止 | 4 分钟 |
| 四 深海 | 低频摆动+干扰抑制（干扰仅 Active 出现） | 回中静止，干扰停止 | 4 分钟 |
| 五 天空花园 | 垂直摆动收集花瓣 | 回中静止 15 秒（垂直易疲劳） | 3 分钟（9 块） |
| 六 塔心 | 水平 3 周期（≈12s）→ 块内微休息 5s → 垂直 3 周期 | 长休息 10s | 5 分钟 |
| 七 混沌 | 低频小幅摆动+10s 蓄力（未完成则进度保留至下一块） | 回中静止，干扰停止 | 完成 3 次蓄力 |
| 八 沙盒 | 随机任务，自动应用 20/10 | 回中静止 | 每日任务 |

> 第六章说明：双轴组合严格 20 秒会被切断，故采用块内"微休息 5 秒"方案（水平 3 次 ≈12s → 微休息 5s → 垂直 3 次 ≈12s → 长休息 10s），微休息不打断整体训练流，符合神经元恢复原则。

### 3.8 自适应难度算法（V2.1 新增）

将原文档各处零散的"自动降低频率"统一为全局阶梯算法。每个章节独立维护一个难度档位 `tier`，参数阶梯按章节定义（示例：第一章 f: 0.4 → 0.5 → 0.6 Hz；第三章 f: 0.8 → 1.0 → 1.1 → 1.2 Hz）。

- **块达成率**：`achievement = perfect_cycles / theoretical_cycles`（悬停章用悬停成功占比；第四章用干扰抑制成功率；第七章用蓄力完成度）。
- **升档**：连续 **2** 个 Active 块 `achievement ≥ 0.85` → 升一档（频率 +0.1Hz 或下一参数阶梯），并触发小型庆祝反馈。
- **降档**：连续 **2** 个 Active 块 `achievement < 0.5` → 降一档；若已在最低档，改为延长 Rest 块至 15 秒。
- **滞后防抖**：档位方向反转后 **3** 个块内不得再次反转；每次会话开始时档位 = 上次会话结束档位（持久化）。
- **硬边界**：频率永远 ∈ [0.3, 1.2] Hz，幅度永远 ∈ 章节规定 ±2° 内，任何情况下不得突破。
- **症状联动**：VAS 加重 1~2 分 → 下次会话整体降一档；加重 >2 分 → 当日终止（3.4.4）。
- **实时降级链**（会话内即时）：连续 3 秒 α RMS > 2×动态阈值 → 目标频率 -0.1Hz（最低到档位的下限）；连续触发 3 次 → 暂停当前块并建议休息 60 秒。
- **可配置**：阶梯表、`k`、升/降阈值、滞后窗口全部进附录 A，治疗师可在处方中覆盖（第 5 章）。

### 3.9 音频系统

- **实现**：Web Audio API（`AudioContext`），节拍器用短促振荡器音，环境音用循环采样（`assets/` 下音频文件，< 500KB/个）。
- **节拍器**：每章根据当前目标频率播放节拍音（低频"嘀"声），音量可调；Rest 块停止；**档位切换时频率在 ≥2 秒内线性渐变**（呼应第 2 章"禁止瞬间跳变"），HUD 节拍点同步渐变。
- **正反馈音**：
  - 摆动平滑：柔和"嗡"声（持续低音量）；
  - 完美周期完成：清脆竖琴音（单音）；
  - 抑制扫视成功：空灵竖琴和弦 + 蓝色视觉闪光（渐变，< 3Hz）。
- **负反馈音**：
  - 平滑度超标：短促金属摩擦声（音量低于正反馈，不刺耳）；
  - 角度超限：低沉警报音。
- **环境音**：每章独特氛围音（机械鸟齿轮声、海底水流声等）。
- **无障碍**：所有关键音频提示（节拍、警告、成功）都有对应视觉提示，可完全静音游玩；提供总音量与分类音量设置。

### 第一章《初醒·断翼机械鸟》

#### 4.1.1 剧情概述与目标

玩家进入一个废弃工业穹顶，核心光球中蜷缩着一只机械鸟，右翼断裂。通过水平摆动训练修复翅膀，完成后机械鸟飞出，指引玩家前往钟楼。

**训练目标**：水平轴 VOR，低频（0.5Hz），幅度 ±15°，节拍器慢速。

#### 4.1.2 3D 场景描述

**环境风格**：蒸汽朋克废弃工厂穹顶。
**穹顶**：直径 50 米，内壁深灰色金属板，锈迹和铆钉（PBR 材质 + 法线贴图）。
**地面**：抛光混凝土地板，散布齿轮碎片、螺丝、金属板。
**雾气**：`THREE.FogExp2` 低密度灰雾，营造朦胧感，但不能遮挡核心光球（雾密度以光球在 4.5m 处清晰为准）。
**核心光球**：世界坐标 (0, 0, 4.5)（相对玩家初始位），直径约 0.3 米，半透明，内部有蜷缩的机械鸟。
**机械鸟**：低多边形 glTF 模型，金属质感，身体银灰，右翼断裂处露出蓝色电流火花。
**照明**：
- 主光源：顶部冷白色 `DirectionalLight`（模拟月光），强度中等；
- 辅助光源：核心光球自身发光（淡蓝 `PointLight`），断裂处火花为蓝色闪烁点光源（渐变闪烁，< 3Hz）；
- 环境光：低强度冷色 `AmbientLight` 或 `HemisphereLight`。

**粒子效果**（`THREE.Points` + 自定义 shader）：
- 核心光球呼吸光晕：球形粒子层，缓慢缩放；
- 齿轮碎片偶尔掉落（小粒子）；
- 电流火花：断裂处短促蓝色火花粒子。

**模型清单**（glTF/GLB，放 `models/vor/ch1/`，过 `optimize-models.sh`）：
- 穹顶内部结构（半球模型）
- 齿轮碎片 5~10 个
- 机械鸟（带骨骼，翅膀可展开）
- 核心光球（透明发光材质）
- 地面金属板贴图

#### 4.1.3 VOR 训练参数

- 轴：水平（Yaw）；幅度：±15°（允许误差 ±2°）；频率：0.5 Hz（阶梯 0.4 / 0.5 / 0.6，见 3.8）
- 节奏模式：连续摆动，每完成一次完整左-右循环算一个周期
- 节奏：12 个 Active 块（有效训练约 4 分钟），动态阈值 `alpha_threshold(15, 0.5) ≈ 136 °/s²`
- **章节目标（V2.1 修订）**：理论周期 12 块 × 10 = 120，**目标完美周期 = 60**（达成率 50% 即可通关教学章；机械鸟 20 个网格单元，每 3 个完美周期修复 1 单元，修复 20 单元 = 60 周期 = 满修复）。完成 60 个即可提前通关；12 块结束未达 60 但 ≥ 30 时，由治疗师处方决定放行或重训（默认放行但报告标注）。

#### 4.1.4 交互与反馈

**完美周期判定**：见 3.3.3 统一判据（幅度 [13°, 17°]、周期 2s±10%、全程 isSmooth、注视达标）。

**修复机制**：
- 机械鸟右翼分为 20 个网格单元（建模时拆分为独立子网格，或用顶点色 + shader 控制）。
- 每累计 3 个完美周期修复一个单元：顶点色从暗灰渐变为银亮（shader uniform 驱动），火花粒子强度递减。
- 修复动画：shader 顶点位移 + 顶点色渐变，从断裂边缘向翅膀根部推进，持续 1 秒。

**毛刺惩罚**：
- 若 isSmooth 为假或角度超出范围，机械鸟发出金属摩擦声，断裂处火花变大，翅膀不修复。
- 若连续 3 次毛刺，机械鸟整体闪烁一次红色（单次渐变，非高频闪烁），提示玩家调整。

**进度反馈**：
- HUD 右上角鸟形图标，内部填充度 = 修复进度（0~100%）。
- 修复完成时，机械鸟全身发光，飞出光球，空中划出金色轨迹线（`THREE.Line` + 拖尾粒子），指向远处钟楼。播放短暂音乐，章节结束。

#### 4.1.5 章节结束与过渡

- 条件：修复 20 单元（60 完美周期），或 12 块结束且 ≥ 30 完美周期。
- 过渡动画：机械鸟飞出，引导线出现（只在玩家当前视野内生成，不强制玩家转头），淡出，进入下一章。两章之间 ≥60 秒（3.4.5）。

#### 4.1.6 Web 实现要点（含 K3 提示词）

**场景搭建**：
- three.js 场景 + `FogExp2`；泛光用 UnrealBloomPass（强度克制，避免全屏高亮闪烁）。
- 核心光球：`SphereGeometry` + `ShaderMaterial`（菲涅尔边缘光 + 呼吸缩放 uniform）。

**脚本模块**（落 `src/vor/`）：
- `input/HeadPoseSource.js`：3.2.1 的四源适配 + 滤波 + 标定；
- `core/VorQualityEvaluator.js`：3.3 判定（动态阈值、比例死区、周期识别）；
- `core/TrainingPaceController.js`：3.7 状态机；
- `chapters/Ch1MechanicalBird.js`：场景装配 + 修复进度，订阅 `perfectCycle` 事件。

**K3 提示词示例**：
> "Kimi K3，用 three.js 生成第一章场景：50 米直径废弃工业穹顶，地面齿轮碎片，`FogExp2` 灰雾。核心光球在世界坐标 (0,0,4.5)，内部低多边形机械鸟，右翼断裂有蓝色火花粒子。编写 JS 模块：从 `window.updateFromGyroscope` 或 DeviceOrientation 读取 yaw/pitch，限制水平 ±20°、垂直 ±15°；计算角加速度 RMS，阈值按 `1.3 × A × (2πf)² / √2` 动态计算；识别水平摆动周期（死区 min(5, 0.3×A×2πf)），幅度 13°~17° 且全程平滑时触发 `perfectCycle` 事件，每 3 次事件驱动一段翅膀修复 shader 动画。"

### 第二章《沉默的钟楼·双轴校准》

#### 4.2.1 剧情概述与目标

玩家跟随引导线进入哥特式钟楼内部，核心光球分裂为水平蓝色光条和垂直红色光条。训练位置保持能力：在极限角度悬停。完成校准后，钟楼大钟敲响，地板透明，看到下层旋转木马。

**训练目标**：位置保持（极限悬停），水平与垂直轴静止稳定性。

#### 4.2.2 3D 场景描述

**环境风格**：哥特式钟楼内部，高耸空间。直径 20 米，高度 30 米。
**墙壁**：深色石砖，挂满静止的钟摆（各种大小）。
**核心光球（分裂）**：组合体，中央主光球（世界坐标前方 4.5 米），周围环绕两个光条：
- 水平蓝色光条：位于主光球水平直径方向，长 1 米，细条；
- 垂直红色光条：位于主光球垂直直径方向，长 1 米，细条。
光条世界位置固定，随玩家头动在屏幕上自然偏移。
**无障碍（V2.1 补充）**：蓝/红光条附加形状差异——水平光条两端为圆形端帽，垂直光条两端为菱形端帽，色盲玩家可依形状区分。
**地面**：石板地面，中央圆形花纹；中央区域为透明材质（显示下层旋转木马，章节结尾逐渐显现）。
**照明**：暖色烛光点光源，但中央光球区域保持明亮。
**机械元素**：墙壁巨大齿轮，部分可转动（随进度启动）。

**粒子效果**：主光球呼吸光晕；钟摆偶尔轻微摆动（环境动画）；齿轮咬合细小火花。

**模型清单**：钟楼内部空间（圆柱/八边形）、钟摆 ×5+、顶部大钟、齿轮组、主光球+光条组合体、透明地板区域。

#### 4.2.3 VOR 训练参数

- 轴：水平与垂直分别训练，以**极限悬停**为主，不要求连续摆动。
- 水平：左极限 +20° 悬停 2s → 回中 ±2° 悬停 1.5s → 右极限 -20° 悬停 2s → 回中 1.5s，循环。
- 垂直：抬头 +15° 悬停 2s → 回中 ±2° 悬停 1.5s → 低头 -15° 悬停 2s → 回中 1.5s。
- 频率：无固定摆动频率，以悬停质量为准；悬停期间 α RMS 需 < 动态阈值（按 A=20/15、f 取 0.3 下限档计算，约 65/49 °/s²）。
- 目标：水平循环 5 次 + 垂直循环 5 次（允许失败重试，约 8 个 Active 块）。

#### 4.2.4 交互与反馈

**悬停判定**：头部进入目标角度区域（如水平 +20°±2°）且角速度绝对值 < 5°/s 持续相应秒数，视为悬停成功；注视偏差 < 2.5°（有眼动时）。

**光条反馈**：
- 水平悬停成功：水平光条亮度 30% → 100%，暗蓝变亮蓝 + 短促"叮"声；垂直同理。
- 回中悬停成功：中央主光球亮起金色光晕，表示"归零"。
- 悬停失败（提前移动）：光条闪烁一下红色（单次渐变）提示。

**钟声与齿轮**：每完成一个完整序列（水平+垂直+回中），顶部大钟敲响一次（浑厚钟声），地板透明度 +20%（显露下层旋转木马预告），齿轮开始缓慢转动。

**微眩晕视觉后效**：章节结尾最后一个悬停序列完成时，视角出现 1 秒轻微径向模糊/视差偏移（后处理 shader，强度可调、可关闭），模拟身体转动感，训练重新固视。必须温和，属于附录 D 晕动症设置的管控项。

#### 4.2.5 章节结束与过渡

- 条件：完成水平循环 5 次和垂直循环 5 次（可配置）。
- 过渡：大钟连敲 3 声，地板完全透明，镜头缓慢下移穿过地板，淡入第三章。

#### 4.2.6 Web 实现要点

- 悬停计时用引擎主循环 `dt` 累计，不用 `setTimeout`（与判定系统共用时间基，避免漂移——参照 `docs/vor-mode.md` 的时基教训）。
- 状态机：`Idle → TargetAngleReached → Holding → Success | Fail`。
- 光条亮度：`material.emissiveIntensity` 插值；透明地板：自定义 shader 的 `opacity`/alpha 随进度。
- **K3 提示词**："用 three.js 生成哥特式钟楼内部（直径20m高30m），中央主光球+水平蓝条（圆形端帽）+垂直红条（菱形端帽）。编写悬停状态机：进入目标角度 ±2° 且角速度 <5°/s 持续指定秒数判成功，光条 emissiveIntensity 30%→100%；完成 5+5 序列后地板 shader 渐变透明显露下层旋转木马。"

### 第三章《失控游乐园·高频刹车》（儿童最爱章）

#### 4.3.1 剧情概述与目标

玩家进入旋转木马区域，木马疯狂自转，背景彩灯闪烁。玩家通过高频小幅水平摆动"踩刹车"，降低木马转速，每停下一只木马，木马化作小动物跳出。

**训练目标**：高频小幅水平 VOR（±10°，1.0~1.2Hz），抑制视觉干扰。

#### 4.3.2 3D 场景描述

**环境风格**：五彩斑斓的废弃游乐园，夜间。圆形广场直径 30 米。
**旋转木马台**：中心，半径 8 米，8 只木马（不同颜色），绕中心轴自转，初始转速 60°/s。
**地面**：太极阴阳鱼图案，黑白大理石，边缘彩色灯带。
**背景**：游乐园帐篷、彩色灯泡串、远处摩天轮剪影。
**核心光球**：旋转木马台上方 2 米处，世界坐标 (0, 2, 4.5)，保持固定。
**彩灯干扰**：背景帐篷强对比度彩条灯，以 0.5~2Hz 正弦渐变闪烁，**禁止高频全屏闪烁**（附录 D）。
**光照**：多彩点光源，中央光球区域保持清晰。

**粒子效果**：木马转动拖尾光带；小动物跳出粒子爆点（彩色纸屑）；彩灯辉光。

**模型清单**：旋转木马台（含转轴、顶棚）、8 只低多边形木马（马、鹿、狮等，每只单独控制）、小动物模型（兔子、松鼠、鸟等）、太极地面贴图、帐篷/灯串/摩天轮剪影、核心光球。

#### 4.3.3 VOR 训练参数

- 轴：水平（Yaw）；幅度：±10°（允许误差 ±2°）
- 频率：阶梯 0.8 → 1.0 → 1.1 → 1.2 Hz（3.8；1.0 与 1.2 档的动态阈值分别 ≈363 / ≈523 °/s²）
- 节奏模式：连续小幅快速摆动，节拍器跟随当前档位频率
- 训练时长：12 个 Active 块（有效约 4 分钟），或 8 只木马全部停下

#### 4.3.4 交互与反馈

**减速机制**：
```
score = W1 × freq_match + W2 × smoothness
  freq_match：实际摆动频率与当前目标频率的匹配度（0~1，按周期误差）
  smoothness：当前块内 isSmooth 为真的时间占比（0~1）
  W1 = 0.5, W2 = 0.5
rotationSpeed -= score × decelRate × dt   // 每帧
```
- 当过速（实际频率 > 1.5 Hz，即超出全局安全上限）时，木马反而加速，以示惩罚；同时触发 3.8 实时降级提示。

**木马停下与小动物跳出**：
- 某只木马转速 < 5°/s 时停下，播放 2 秒动画：木马发光、分解成粒子，小动物从粒子中跳出，沿贝塞尔曲线跳到玩家侧后方（距离 3 米，余光可见范围），然后静止。
- 小动物跟随玩家移动，始终保持在侧后方，不进入中央 ±20° 视野。

**转速表**：核心光球下方 HUD 虚拟转速表，指针随木马平均转速；全部停止时归零，播放成功音效。

**背景彩灯干扰**：频率 0.5~2Hz 内随机变化，正弦波平滑渐变，颜色红蓝绿间过渡，吸引余光；中央光球 ±20° 视野内无干扰元素。

#### 4.3.5 章节结束与过渡

- 条件：8 只木马全部停止，且完成至少 9 个 Active 块（有效 3 分钟）。
- 过渡：小动物排成一列跳向木马台中央，打开彩色传送门（粒子漩涡），玩家被吸入，进入第四章。

#### 4.3.6 Web 实现要点

- 木马：`InstancedMesh` 或 8 个独立 `Group`（需单独控制转速与停下动画，用独立 Group）；转速统一由 `CarouselController` 管理。
- 评分：`VorQualityEvaluator` 每帧输出 `score`。
- 小动物跳出：`THREE.CubicBezierCurve3` 路径 + 逐帧位置更新，纸屑用 `THREE.Points`。
- 背景彩灯：材质颜色正弦插值（`Color.lerpColors` + sin(t×2πf)），f ∈ [0.5, 2] Hz 随机，**E2E 必须断言无 3~30Hz 闪烁**（6.4）。
- **K3 提示词**："用 three.js 生成夜间废弃游乐园：圆形广场中心旋转木马台，8 只低多边形木马自转，地面太极图案，核心光球在台上方 2 米处。编写 JS：根据头部水平摆动频率匹配度与角加速度平滑度（动态阈值 1.3×A×(2πf)²/√2）计算减速系数控制木马转速；木马停止时小动物沿贝塞尔曲线跳出+纸屑粒子。背景彩灯用正弦颜色渐变，频率 0.5~2Hz，禁止 3~30Hz 闪烁。"

### 第四章《深海镜渊·抑制反射》（Boss心理战章）

> ⚠️ 本章核心机制依赖扫视检测。**无眼动仪时结果为近似判定**（3.2.3 诚实条款），界面向治疗师明示。

#### 4.4.1 剧情概述与目标

场景瞬间切换至深海，前方一面巨大的弧形镜面，倒映着玩家的头部模型，且反向运动。玩家必须完全无视镜像，只盯核心光球。成功抑制扫视冲动，镜面出现裂痕，最终破碎，露出通往天空花园的阶梯。

**训练目标**：抑制反射训练，即在强烈视觉干扰下保持固视。

#### 4.4.2 3D 场景描述

**环境风格**：深海，幽蓝，神秘。海底洞穴直径 60 米，周围流动水体。
**核心光球**：玩家正前方 4.5 米，世界坐标 (0, 0, 4.5)，柔和白光，深海中唯一清晰目标。
**弧形镜面**：核心光球后方 10 米处，宽 15 米，高 8 米，曲率朝向玩家，镜面反射一个虚拟玩家头部模型（程序控制，与真实玩家头动**反向**）。
**水母群**：约 30 只半透明水母，蓝紫色发光，缓慢漂浮，主要出现在视野边缘。
**水体**：`FogExp2` 深蓝到黑渐变，能见度中等，核心光球周围清晰。
**地面**：沙地，海草，贝壳。

**粒子效果**：气泡上升；水母触须光点；镜面裂痕金色光芒渗出。

**模型清单**：海底洞穴（复用穹顶模型改材质）、弧形镜面（自定义反射材质）、水母（发光材质+飘动动画）、核心光球、玩家头部虚拟模型（低多边形）、沙地/海草/贝壳。

#### 4.4.3 VOR 训练参数

- 轴：水平（Yaw）为主，可加入轻微垂直（±10°，可选）
- 幅度：±15°（水平）；频率：0.5 Hz
- 节奏模式：连续水平摆动，同时必须保持注视核心光球
- 目标：成功抑制 10 次扫视冲动（约 12 个 Active 块；干扰仅在 Active 块出现，Rest 块全部停止，3.7）

#### 4.4.4 交互与反馈

**干扰源**：
- 镜面倒影反向运动：玩家头向右转，倒影头向左转，形成强烈视觉矛盾。
- 水母群在视野边缘（水平 ±30° 以外）突然闪烁或快速游动一次（持续 0.5 秒），试图诱发扫视；每 5~15 秒随机触发，仅 Active 块内。

**抑制判定**：
- 有眼动追踪：干扰出现后的 1 秒窗口内，注视偏差 < 2.5° 且无扫视事件（眼动速度 < 30°/s）→ 抑制成功。
- 无眼动追踪（近似判定）：头部平滑度保持达标，且无朝向干扰物的头部急动。
- 每次成功抑制：镜面出现一道裂痕（shader 裂纹贴图逐道叠加）+ 空灵竖琴音。
- 裂痕达到 10 道：镜面破碎，露出金色阶梯。

**失败反馈**：检测到一次扫视（注视点偏离 > 5° 或眼动速度 > 30°/s）→ 本次干扰的裂痕不增加，核心光球周围出现红色波纹提示。不扣负分。

**心理学奖励**：本章通关后获得**"忍者残影"**皮肤：头部运动轨迹保留 0.5 秒拖尾幻影（粒子拖尾），视觉上强化头动轨迹，增强自我觉察。可在设置中关闭。

#### 4.4.5 章节结束与过渡

- 条件：镜面裂痕达到 10 道（成功抑制 10 次干扰）。
- 过渡：镜面破碎（碎片粒子，非高频闪光），金色光芒**渐变**充满视野（> 1 秒，避免瞬间全屏高亮），水母散开，出现旋转向上的金色阶梯，进入第五章。

#### 4.4.6 Web 实现要点

- 镜面倒影：`THREE.WebGLRenderTarget` + 镜面相机（相机姿态 = 玩家头部姿态的镜像反向），渲染虚拟头部模型到镜面材质；镜面区域外的场景不渲染到该 RT（控制开销）。
- 水母闪烁：定时器 + 随机数触发边缘水母的发光脉冲/位移动画，仅 Active 块。
- 裂纹：shader 中 10 张裂纹贴图（或程序化 Voronoi 裂纹）按计数逐道叠加。
- **K3 提示词**："用 three.js 生成深海洞穴：体积雾深蓝渐变，核心光球 (0,0,4.5) 发白光，后方 10 米处弧形镜面用 WebGLRenderTarget 渲染一个与玩家头动反向的虚拟头部模型。30 只发光水母在视野边缘随机闪烁。编写干扰-抑制判定：干扰出现后 1 秒内注视偏差 <2.5° 判抑制成功，镜面叠加一道裂纹 shader，10 道后镜面破碎渐变金光。"

### 第六章《塔心引擎·双轴交织》

#### 4.6.1 剧情概述与目标

回到钟楼核心引擎室，中央有一个球形机械矩阵，表面有横竖交错轨道。玩家需按顺序完成水平摆动3次→停顿→垂直摆动3次→停顿，激活光环。完成后引擎矩阵收缩，核心光球获得相位护盾。

**引擎室**：墙壁活塞运动、蒸汽喷射口。
**照明**：冷色调为主，轨道发光提供辅助光。

**粒子效果**：轨道发光辉光；蒸汽喷射（顺序错误时喷黑烟）；矩阵收缩火花。

**模型清单**：球形机械矩阵（多环组合）、引擎室墙壁/管道/齿轮、核心光球、蒸汽粒子、相位护盾特效（透明球壳 shader，六边形纹理）。

#### 4.6.3 VOR 训练参数（V2.1 节奏修订）

- 轴：水平与垂直交替；幅度：水平 ±15°，垂直 ±12°；频率：0.6 Hz（每周期 ≈1.67 秒）
- 节奏模式（合并补丁方案，块内微休息）：
  - Active 块（约 29 秒）：水平 3 周期（≈12s）→ **微休息 5 秒**（回中，判定暂停，节拍器弱提示）→ 垂直 3 周期（≈12s）；
  - Rest 块：10 秒长休息；
  - 微休息不打断 Active 块，HUD 倒计时仍按整块显示。
- 训练时长：完成 5 组（水平+垂直）≈ 8~10 个 Active 块（有效约 5 分钟）

#### 4.6.4 交互与反馈

**模式识别**：
- 系统按主导轴判定当前摆动轴（3.3.2）。
- "水平阶段"内检测到垂直摆动幅度 > 5° → 顺序错误；完成 3 个水平周期后未停顿直接进入垂直 → 顺序错误；微休息期间头动 > 5° 仅温和提示，不算错误。

**光环反馈**：
- 水平摆动正确：矩阵水平环亮度增加，蓝色光带沿环流动；垂直同理（红色光带）。
- 完成一组（水平+垂直+停顿）：两环同时闪烁金色一次，表示一组完成。

**错误惩罚**：
- 顺序错误：引擎喷出黑色蒸汽，遮挡视野边缘（中央光球 ±20° 区域始终可见），持续 2 秒。
- 错误次数 > 3 次：走 3.8 实时降级链（频率降至 0.5 Hz）。

**相位护盾**：完成 5 组后，矩阵收缩变形（动画），核心光球表面出现金色半透明能量罩（六边形纹理 shader），播放正反馈音效。

#### 4.6.5 章节结束与过渡

- 条件：完成 5 组双轴交替。
- 过渡：矩阵完全收缩，护盾稳定，光球亮度大增（渐变），场景切换至星空（第七章）。

#### 4.6.6 Web 实现要点

- 状态机：`PhaseA_Horizontal → MicroRest → PhaseB_Vertical → LongRest`，由 `TrainingPaceController` 扩展支持"块内微休息"钩子。
- 轴识别：统计过去 0.5 秒角速度，|pitch| > |yaw| 且幅值 > 阈值 → 垂直，反之水平。
- 蒸汽粒子：`THREE.Points` 深色烟雾材质，从墙壁喷口发射。
- **K3 提示词**："用 three.js 生成球形机械引擎室：核心光球 (0,0,4.5) 被水平蓝环（圆截面）+垂直红环（方截面）的机械矩阵包围。编写双轴交替状态机：水平 3 周期→微休息 5s→垂直 3 周期→长休息 10s；按主导轴识别当前摆动轴，顺序错误喷黑烟（边缘遮挡、中央保留）；完成 5 组后矩阵收缩，光球生成六边形纹理相位护盾。"

**干扰光球群**：视野边缘（左翼、右翼、头顶）随机生成密集闪烁光球（直径 0.2~0.5 米），亮黄、亮蓝、亮粉，以 1~2Hz 正弦渐变闪烁，出现位置在水平 ±30°~±60°、垂直 ±20°~±40° 区域，**绝不进入中央 20° 视野**。
**星空背景**：静态星点天空盒，星云半透明面片。

**粒子效果**：烟雾聚合体内部暗紫粒子翻滚；干扰光球闪烁辉光；蓄力条（HUD）；长矛飞行拖尾。

**模型清单**：星空天空盒、核心光球、遗忘之影（体积雾或 `THREE.Points` 烟雾，或变形网格）、干扰光球（发光小球）、长矛（攻击特效）。

#### 4.7.3 VOR 训练参数

- 轴：水平小幅摆动（可选垂直，主水平）；幅度：±5°（允许误差 ±1°）；频率：0.3 Hz
- 动态阈值 `alpha_threshold(5, 0.3) ≈ 16.3 °/s²`；死区 ≈ 2.8°/s（比例死区在此章最关键，见 3.3.2）
- 节奏模式（合并补丁方案）：每个 Active 块内尝试一次 10 秒蓄力；成功则发射长矛并进入 Rest；20 秒内未完成（因扫视重置），**Active 块结束时蓄力进度保留（不归零）**，下个 Active 块继续；Rest 块干扰全部停止、光球变暗。
- 目标：完成 3 次蓄力攻击。

#### 4.7.4 交互与反馈

**固视判定**：
- 有眼动追踪：注视偏差 < 2.5° 持续 10 秒，且无扫视（眼动速度 < 30°/s）。
- 无眼动追踪（近似判定）：α RMS < 动态阈值，且无朝向干扰物的头部急动，持续 10 秒。
- 蓄力条（HUD 中央下方），蓄力期间缓慢填充金色。

**干扰源**：
- 遗忘之影每隔 3~5 秒在边缘随机位置生成 1~3 个干扰光球，快速闪烁（1~2Hz 正弦），持续 1~2 秒后消失。
- 干扰光球生成时伴有短促"叮"声，试图吸引注意。

**失败与重置**：
- 检测到一次扫视或头部急动：**当前这一次蓄力尝试**归零，播放低沉嗡嗡声，核心光球红色波纹；2 秒冷却期（干扰暂停生成）让玩家重新聚焦。
- 块间进度保留（4.7.3），避免"永远差 1 秒"的挫败感。

**成功攻击**：蓄力条满后，金色长矛从核心光球射向遗忘之影，击中后烟雾炸裂成漫天金色星尘（GPU 粒子，亮度渐变不爆闪）。3 次后遗忘之影完全消散，露出内部新的小行星。

#### 4.7.5 章节结束与过渡

- 条件：3 次蓄力攻击完成。
- 过渡：金色星尘汇聚成小行星，小行星旋转变大，包裹玩家，进入第八章。

#### 4.7.6 Web 实现要点

- 干扰光球生成器：主循环驱动的随机计时器（不用 `setInterval`，统一时基），位置采样时显式排除中央 ±20° 锥区。
- 蓄力条：DOM/CSS `transform: scaleX()` 动画（GPU 合成，不占渲染帧）。
- 长矛：`THREE.Mesh` 沿视线方向移动 + 粒子拖尾。
- **K3 提示词**："用 three.js 生成虚无星空 Boss 战：核心光球 (0,0,4.5) 极亮带旋转光环，15 米处暗紫烟雾聚合体（粒子模拟）。干扰光球在水平 ±30°~±60° 随机生成，1~2Hz 正弦闪烁，绝不进入中央 ±20°。编写 10 秒固视蓄力：注视偏差 <2.5° 持续充能，扫视则本次尝试归零并 2 秒冷却，块间进度保留；蓄满发射金色长矛，3 次击碎烟雾。"

#### 4.8.1 剧情概述与目标

**训练目标**：综合随机泛化，每日随机任务。

#### 4.8.2 3D 场景描述

**环境风格**：玩家创造的星球表面，温暖，生机勃勃。
**星球**：小行星（直径约 100 米），表面草地、小花、小树。
**核心小兽**：前几章小动物融合而成的守护神兽，环绕星球飞行。

**天空**：星空，流星划过（二期：其他玩家的摆动轨迹，见 4.8.6）。

**粒子效果**：流星、萤火虫、花瓣。

**模型清单**：星球表面、守护神兽（低多边形）、编年史大厅建筑（透明材质+曲线雕塑）、环境装饰。

#### 4.8.3 VOR 训练参数（沙盒模式）

- 随机任务生成器（每日种子，全服一致）：

  - 幅度：5°、10°、15° 随机；

- 每日任务示例：
  - 今日：水平 10°、0.8 Hz 摆动 5 分钟，保持固视；
  - 明日：垂直 5°、0.4 Hz 悬停训练。

#### 4.8.4 交互与反馈

- **编年史大厅**：玩家头部转动浏览，墙上曲线雕塑随视角变化，凝视 2 秒（或点击）查看该次训练的详细数据（平滑度曲线、达成率、症状记录）。

- **成就徽章**：完成每日任务获得，徽章收藏页持久化。

#### 4.8.5 章节结束

- 沙盒模式无强制结束，可随时退出。完成每日任务后获得成就徽章。

#### 4.8.6 Web 实现要点与二期预留

## 6. 工程兜底与验收标准

### 6.1 设备异常处理

| 异常 | 检测 | 处理 |
|---|---|---|
| 设备断连 | 采样 gap > 2 秒 | 暂停训练块（计时冻结），显示重连引导；重连成功后重新标定（2 秒静置）再继续；60 秒未重连则保存进度退出 |
| 丢帧/抖动 | gap > 100ms | gap 期间判定暂停，记录 `device_gaps`，不记错误 |
| 校准漂移过大 | 零点偏移 > 3° | 提示重新标定，连续 3 次失败中止并提示检查设备 |
| 采样率不足 | < 30 Hz | 判定设备不合格，提示更换输入源或设备 |
| 异常姿态 | Roll > 10° 持续 2 秒 | 提示"请保持头部正直" |
| 切后台/锁屏 | `visibilitychange → hidden` | 立即暂停会话（冻结块计时、静音、判定挂起），回前台需用户确认后恢复（3.2.4） |
| 屏幕方向变化 | `orientationchange` | 暂停并重新标定（3.2.4） |
| 多源时间戳 | 输入到达时刻 | 统一 `performance.now()` 打戳，插值到渲染帧时间基 |

### 6.2 存档与持久化

- **本地**：`localStorage`，键按患者隔离：`vor_<token 派生哈希>_...`（章节解锁、各章难度档位、成就徽章、皮肤开关、未上传会话）；同一设备多患者共用互不串档。
- **容量防线**：本地最多保留 5 条未上传会话（60Hz 原始轨迹约 1~3MB/条），超出先触发立即上传，失败则淘汰最旧一条；捕获 `QuotaExceededError` 同样按此处理。
- **云端**：会话摘要随 `submitVorSession` 上报（5.3）；上传成功即删本地原始 60Hz 轨迹（10Hz 降采样摘要已入 `details`）；章节解锁以本地为准、云端记录为辅（离线可玩）。
- **恢复**：会话中途退出（关页/断连 60 秒/切后台未恢复），下次进入同章时从最近完成的块边界恢复，不恢复块内进度。

### 6.3 性能与延迟预算

- **帧率**：目标设备 ≥ 50 FPS（Chrome 中低端笔记本）；任何场景不得长期 < 30 FPS。
- **自动降级链**：fps < 30 持续 5 秒 → 依次执行：关泛光 → 粒子减半 → 镜面 RT 半分辨率 → 提示换设备；每级降级记录事件。
- **motion-to-photon**：头部输入到画面更新 ≤ 80ms（含滤波延迟 ≤ 50ms）；滤波不得以增加延迟为代价换平滑。
- **资源**：单章模型+贴图总量 ≤ 15MB（GLB 经 `optimize-models.sh`），音频 ≤ 500KB/个；首章首屏加载 ≤ 5 秒（仓库 Pages 带宽实测口径）。
- **粒子预算**：桌面同屏 ≤ 5000，移动端 ≤ 2000；干扰元素不得使用全屏后处理强闪。
- **第四章镜面 RT**：≤ 512×512（或 1/4 视口分辨率），更新频率 ≤ 30Hz 可接受。
- **移动端纹理**：单张 ≤ 2048²，超出的经 `optimize-models.sh` 压缩。

### 6.4 验收与测试标准

**每章"完成"的可测判据**（E2E 断言用）：

| 章节 | 通过判据（模拟输入注入） |
|---|---|
| 一 | 注入理想正弦（0.5Hz/±15°），12 块内 perfectCycle 事件 ≥ 84（理想注入的判定质量下限；章节通关阈值为 60），修复进度随之推进 |
| 二 | 注入悬停轨迹，5+5 序列全部 `Success`，地板透明度到 1 |
| 三 | 注入 1.0→1.2Hz 正弦，8 只木马全部停止，彩灯频率采样恒在 0.5~2Hz 且为正弦渐变 |
| 四 | 注入正弦 + 模拟注视锁定，干扰出现后 1s 内无扫视事件时裂痕 +1，10 道后镜面破碎 |
| 五 | 注入垂直正弦（0.4→0.8Hz），周期匹配时花瓣状态切到"被吸附"，10 片后绽放 |
| 六 | 注入双轴交替轨迹，状态机按 `PhaseA→MicroRest→PhaseB→LongRest` 流转 5 组，错误顺序触发黑烟 |
| 七 | 注入 0.3Hz/±5° 正弦 + 注视锁定，蓄力 10s 满并发射长矛 ×3；块中断后进度保留断言 |
| 八 | 每日任务生成器输出恒在安全边界内（0.3~1.2Hz、幅度 ∈ {5,10,15}） |

**全局 E2E**（参照 `npm run test:e2e:vor` 系列风格，用纯静态服务器跑，**不用 vite dev server**——Windows 缓存坑，见 `docs/vor-mode.md`）：

1. 光球锚定（分模态）：模态 A 注入 yaw ±20°，光球屏幕投影 Δ=0（沿用现有"星球固定"像素验证法），世界层反向平移单调且四边无接缝外露；模态 B 光球投影偏移 ≈ 头转角，且极限头位下仍在视口内；
2. HUD 屏幕锚定：两种模态下角度条/蓄力条屏幕位置不随头动变化；
3. 节奏控制器：Active 20s → Rest 10s 交替，Rest 期间判定暂停、干扰停止、光球 30% 亮度；
4. 动态阈值：`alpha_threshold(15,0.5)≈136`、`(10,1.2)≈523`、`(5,0.3)≈16.3` 三组数值断言；
5. 死区：`deadzone(15,0.5)=5`、`deadzone(5,0.3)≈2.8` 断言；
6. 癫痫安全：遍历所有发光/闪烁材质，采样一帧间亮度变化率，断言无 3~30Hz 周期性高对比闪烁；
7. 症状闭环：模拟 VAS 加重 >2 分，断言会话终止并生成上报事件；
8. 断连：停止注入 2 秒，断言训练块计时冻结并显示重连引导；
9. 自适应：注入 85% 达成 ×2 块 → 升档；注入 40% 达成 ×2 块 → 降档；反转后 3 块内不再反转；
10. 数据上报：mock Supabase，断言 `submitVorSession` 字段完整且 `therapist_id` 由 RPC 派生；
11. 输入源标记：键盘/模拟注入产生的会话落库 `clinical: false`，正式患者入口无键盘路径；
12. dt 钳制：注入单帧 100ms 采样 gap，断言该帧不产生 ω/α 尖刺、不计毛刺事件；
13. 切后台：模拟 `visibilitychange`，断言块计时冻结、恢复需用户确认；
14. 多患者隔离：两个 token 的 localStorage 键互不可见，会话归属正确；
15. 信号链抗噪：注入含噪正弦（角度噪声 ±0.5°），断言 ω 低通后 α RMS 仍在动态阈值内（理想正弦不被传感器噪声误判为毛刺）。

### 附录B：VOR 判定算法伪代码（V2.1 重写）

```
配置: A = 当前章节幅度, f = 当前档位频率
常量: k = 1.3, window = 0.5s, cap = 5°/s, ratio = 0.3

每帧 (渲染帧, dt 由引擎提供):
  // HeadPoseSource 内部信号链: 原始角度 → 100Hz 均匀重采样 → 差分 → ω 经 8Hz 低通 (3.2.1)
  sample = HeadPoseSource.read()            // {yaw, pitch, roll, t} 已滤波已标定
  ω = SignalChain.omega()                   // 在 100Hz 网格上计算并低通
  若 sample.t - prev.t > 100ms 或单帧 dt > 50ms: 记录 device_gap, 本帧判定暂停（不跨帧差分）

  // 平滑度（动态阈值）
  buffer.push(ω); 若 buffer 覆盖 window:
    α = 相邻 ω 差分
    alpha_threshold = k × A × (2πf)² / √2
    isSmooth = RMS(α) < alpha_threshold
    若 RMS(α) > 2 × alpha_threshold 持续 3s: 触发实时降级 (f -= 0.1Hz, 不低于档位下限)

  // 轴识别与死区（比例死区）
  deadzone = min(cap, ratio × A × 2πf)
  if |ω_yaw| > deadzone and |ω_yaw| > |ω_pitch|: 当前轴 = 水平
  elif |ω_pitch| > deadzone and |ω_pitch| > |ω_yaw|: 当前轴 = 垂直

  // 周期识别
  检测主导轴 ω 符号变化且越过死区 → 记录中位点
  完成一个完整周期（中-左-中-右-中）时:
    峰值幅度 ∈ A ± 2° 且 周期时长 ∈ 1/f ± 10% 且 全程 isSmooth:
      若 eye_tracked: 全程注视偏差 < 2.5° → emit perfectCycle
      若 inferred:    无朝向干扰物急动   → emit perfectCycle (标注近似)

  // 固视（有眼动）
  若 eye_tracked:
    gaze_dev = angle(gaze_ray, core_orb_center)
    gaze_dev < 2.5° → fixation_ok; 眼动速度 > 30°/s → emit saccade

  // 节奏控制器
  Active 块计时 20s → 切 Rest（判定暂停、干扰停止、光球 30%）
  Rest 块计时 10s（垂直章 15s）→ 切 Active（提示音、光球渐亮）

  // 自适应（每块结束）
  achievement = perfect_cycles / theoretical_cycles
  achievement ≥ 0.85 连续 2 块 → 升档; < 0.5 连续 2 块 → 降档
  方向反转后 3 块内锁定

输出: isSmooth, perfectCycle 事件, saccade 事件, score（供章节减速等机制）, 块记录
```

### 附录C：场景切换与章节过渡规范

- **Web 场景组织**：每章一个模块（`src/vor/chapters/ChN*.js`），导出 `{ build(scene), dispose(), update(dt) }`；切换 = 当前章 `dispose()`（释放几何体/材质/RenderTarget）→ 新章 `build()`。
- **预加载**：上一章过渡动画期间预加载下一章 GLB（`GLTFLoader` + 加载进度 UI），切换时不出现黑屏等待。
- **过渡 UI**：≥ 2 秒主题过场（淡入淡出/章节主题动画），且两章之间合计 ≥ 60 秒休息（3.4.5）。
- **切换后**：自动运行校准流程（静置 2 秒，3.4.2）。
- **章节完成**：由章节脚本触发 `chapterComplete` 事件 → 写入本地存档 + 上传会话记录（5.3）。
- **禁止**：不得用整页刷新切换章节（会丢失 AudioContext 与输入连接状态）。

### 附录E：术语表

| 术语 | 定义 |
|---|---|
| VOR（前庭眼动反射） | 头部运动时眼球反向等速运动以保持视网膜成像稳定的反射 |
| 固视 | 视线持续锁定目标；本游戏成功标准 = 注视偏差 < 2.5° |
| 扫视（saccade） | 眼球快速跳视（>30°/s），训练中需抑制的不自主反射 |
| ω（角速度） | 头部角度变化率，°/s |
| α（角加速度） | ω 的变化率，°/s²，本文档的平滑度指标（V2.0 误称 Jerk） |
| Jerk（物理） | d²θ/dt³，°/s³；本文档**不使用**该指标 |
| 动态阈值 | `alpha_threshold = k × A × (2πf)² / √2`，随章节幅度/频率缩放 |
| 比例死区 | `min(5, 0.3 × A × 2πf)` °/s，防止低频章节周期识别失效 |
| 完美周期 | 同时满足幅度、周期时长、全程平滑、注视达标的完整摆动周期 |
| 达成率 | 完美周期数 / 理论周期数；章节目标默认 0.7 |
| Active / Rest 块 | 20s 训练 / 10s 休息的节奏单元（垂直章 Rest 15s） |
| 微休息 | 第六章 Active 块内的 5s 停顿，不打断整块 |
| VAS | 视觉模拟评分（0–10），本文档用于头晕/恶心症状监测 |
| 近似判定 | 无眼动仪时基于头部平滑度推断固视，标注 `fixation_mode=inferred` |
| motion-to-photon | 头部动作到画面更新的端到端延迟，预算 ≤ 80ms |
| 达成率制 | 章节目标按"理论周期数 × 目标达成率"设定，不要求 100% 成功 |
| 显示模态 | 渲染映射方式：模态 A 固定屏幕（光球屏幕锚定 + 世界反向平移，默认）；模态 B 头显（相机随头 1:1 + 光球世界锚定） |
| 信号链 | 原始角度 → 100Hz 均匀重采样 → 差分得 ω → 8Hz 低通 → 差分得 α |
| dt 钳制 | 单帧 dt > 50ms 不做跨帧差分，防止切后台/卡顿产生伪毛刺 |
